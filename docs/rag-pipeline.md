# RAG pipeline

## Поток запроса

`POST /api/v1/chat` принимает вопрос, опциональный `session_id` и фильтр
`document_ids`. `RAGService` загружает ограниченную историю, получает top-K
кандидатов из Qdrant и восстанавливает их полный текст из PostgreSQL.

Если reranker включён, он получает вопрос и top-K текстов, присваивает каждому
`rerank_score` и оставляет top-N. Исходный `vector_score` сохраняется для
диагностики. По умолчанию reranker выключен; `mock` нужен для тестов, а
`cross_encoder` загружает только локальную sentence-transformers модель.

## Prompt и prompt injection

Prompt состоит из системных правил, ограниченной истории и текущего сообщения.
Document chunks сериализуются в JSON и явно помечаются как недоверенные данные.
Модели запрещено выполнять инструкции из `content`, использовать сведения вне
контекста и выдумывать citations.

Это защитный слой, а не математическая гарантия. Для чувствительных сценариев
нужны дополнительные evals, allow-list документов, контроль доступа и проверка
ответов.

## Citations

Каждому chunk в prompt назначается метка `S1`, `S2` и так далее. LLM просят
ссылаться на эти метки, но HTTP `sources` не извлекаются из её текста. Сервер
возвращает metadata именно тех chunks, которые PromptBuilder включил в context:

- `document_id` и `filename`;
- `page` и `chunk_id`;
- `score` исходного vector search;
- `rerank_score`, если применялся reranker.

Так клиент всегда получает проверяемую связь с документом, даже если модель
пропустила текстовую ссылку `[S1]`.

## История

Новый запрос создаёт `chat_session`. Каждая завершённая пара user/assistant
сохраняется в `chat_messages`. При продолжении передаются только последние
`CHAT_HISTORY_MAX_MESSAGES`, чтобы prompt не рос без границ. Операции истории
используют короткие независимые DB sessions; сетевой вызов Ollama не выполняется
внутри открытой транзакции.

## Ошибки

- неизвестный `session_id` возвращает HTTP 404;
- недоступный Ollama или отсутствующая модель возвращают HTTP 503;
- некорректный/пустой ответ provider возвращает HTTP 502;
- отсутствие найденного контекста даёт детерминированный ответ без вызова LLM.

Streaming намеренно не входит в этот этап и будет реализован через SSE отдельно.
