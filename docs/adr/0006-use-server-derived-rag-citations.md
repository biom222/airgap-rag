# ADR 0006: Формировать RAG citations на сервере

- Статус: принято
- Дата: 2026-10-08

## Контекст

LLM может пропустить, перепутать или выдумать текстовые ссылки на источники.
Клиенту при этом нужна проверяемая связь ответа с реально использованными
document chunks.

## Решение

PromptBuilder нумерует выбранные chunks как `S1`, `S2` и просит модель ссылаться
на эти метки. Однако структурированный массив `sources` формирует application
service напрямую из chunks, вошедших в prompt. Ответ LLM не является источником
metadata citation.

## Альтернативы

- разбирать `[S1]` из свободного текста модели: хрупко и не защищает от
  выдуманных ссылок;
- требовать structured output от каждой модели: полезно позже, но связывает RAG
  слой с возможностями runtime и всё равно требует серверной валидации;
- возвращать все top-K результаты: проще, но часть источников не попадает в
  ограниченный prompt и фактически не использовалась моделью.

## Последствия

- metadata citations всегда соответствует переданному модели context;
- `vector_score` и `rerank_score` доступны для диагностики;
- текстовая ссылка модели может отсутствовать, но structured source сохранится;
- citations показывают использованный контекст, а не доказывают причинность
  каждого предложения ответа.
