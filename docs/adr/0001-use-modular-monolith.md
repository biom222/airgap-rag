# ADR 0001: использовать modular monolith

## Статус

Принято.

## Контекст

AirGapRAG включает HTTP API, background jobs, document processing, vector
retrieval и local inference. Эти подсистемы требуют явных границ, но проект не
имеет нагрузки или независимых команд, оправдывающих микросервисы.

## Решение

Использовать одну Python codebase с модулями по ответственности. API и worker
могут запускаться отдельными процессами и контейнерами, но разделяют domain
contracts, configuration и database schema.

## Обоснование

Подход сохраняет понятные границы и позволяет независимо масштабировать API и
worker без преждевременного добавления сетевых контрактов и распределённых
failure modes.

## Рассмотренные альтернативы

- Микросервисы для ingestion, retrieval и inference.
- Плоское FastAPI-приложение, где routers напрямую вызывают infrastructure.
- Многоуровневая Clean Architecture с отдельным классом для каждой операции.

## Последствия

- Границы модулей контролируются структурой imports и tests.
- Компоненты нельзя независимо выпускать как отдельные продукты.
- Provider interfaces оставляют возможность вынести inference или workers при
  появлении измеренной необходимости.
